# Requirements Document

## Introduction

Text Bridge Avatar is the bridge that delivers LLM text output to the browser Anam avatar. It integrates `WS /ws-anam` at `server.py:271` (initial greeting `こんにちは。私はAIアバターアシスタントです。何かお手伝いできますか？` / `ping→pong`), `LLMTextBridgeProcessor` at `bot.py:54` (fan-out to `set[WebSocket]`) and `LLMTextForwarder` at `bot.py:96` (capturing `TextFrame`/`LLMFullResponseEndFrame`), and frontend `createClient` at `static/script.js:67` / `handleLLMText/handleLLMEnd` at `static/script.js:226` (`createTalkMessageStream`/`streamMessageChunk`/`endMessage`/`interruptPersona`), decoupling server inference from cloud rendering.

## Boundary Context (Optional)
- **In scope**: `/ws-anam` WebSocket management, LLM text broadcast, Anam SDK initialization/stream generation/TTS chunk delivery/interrupt
- **Out of scope**: STT/VAD/LLM inference itself (`voice-pipeline-core`), Vonage audio relay (`audio-connector-bridge`), Vonage session issuance, two-pane layout
- **Adjacent expectations**: `voice-pipeline-core` supplies `TextFrame`, `audio-connector-bridge` supplies audio input, `vonage-media-frontend` publishes Anam MediaStream to Vonage, `connection-lifecycle` controls ws-anam connection timing

## Requirements

### Requirement 1: /ws-anam WebSocket Management

**Objective:** As a browser, I want to connect to `/ws-anam` and receive LLM text, so that the Anam avatar can speak

#### Acceptance Criteria
1. When a browser connects to `WS /ws-anam`, the Text Bridge Avatar shall `await websocket.accept()` and log `Browser connected to /ws-anam` before executing `LLMTextBridgeProcessor.add_client(websocket)` (`server.py:280`)
2. When a client is added, the Text Bridge Avatar shall sequentially send `{"type":"llm_text","text":"こんにちは。私はAIアバターアシスタントです。何かお手伝いできますか？"}` and `{"type":"llm_end"}` via `await websocket.send_json` (`server.py:284`) — greeting is hardcoded Japanese literal, not generated by LLM (implicit rule now explicit)
3. When `ping` text is received, the Text Bridge Avatar shall return `await websocket.send_text("pong")` (`server.py:292`) — note: `receive_text` is used, so `ping` must be plain text not JSON; JSON `{"type":"ping"}` will be ignored (edge case now explicit)
4. When the WebSocket is disconnected, the Text Bridge Avatar shall execute `bridge.remove_client(websocket)` and log `Browser disconnected from /ws-anam` (`server.py:297`)
5. If an exception occurs during greeting send, then the Text Bridge Avatar shall log `Failed to send greeting: {e}` via `logger.warning` and keep the connection alive
6. While multiple browsers are connected, the Text Bridge Avatar shall fan-out the same greeting to each new client independently (implicit multi-tab behavior now explicit)

### Requirement 2: LLM Text Fan-out Delivery

**Objective:** As a system, I want LLM streaming text reliably delivered to all connected browsers, so that avatars speak in sync across multiple tabs

#### Acceptance Criteria
1. When `LLMTextForwarder.process_frame` receives a `TextFrame`, the Text Bridge Avatar shall execute `await self._bridge.broadcast_text(frame.text)` before `await self.push_frame(frame, direction)` (`bot.py:104`) — order ensures bridge receives before downstream transport
2. When `LLMFullResponseEndFrame` is received, the Text Bridge Avatar shall execute `await self._bridge.broadcast_end()` before `push_frame` (`bot.py:107`)
3. When `LLMTextBridgeProcessor.broadcast_text(text)` is called, the Text Bridge Avatar shall attempt `await ws.send_json({"type":"llm_text","text":text})` for all `ws` and collect failed `ws` into `disconnected` then `discard` after the loop (`bot.py:68`) — failed clients are silently removed without logging (gap flagged: should log count)
4. When `broadcast_end()` is called, the Text Bridge Avatar shall send `{"type":"llm_end"}` to all `ws` with the same discard logic (`bot.py:78`)
5. The Text Bridge Avatar shall keep `_text_bridge` as the module singleton at `bot.py:89` and share via `get_text_bridge()` — singleton is in-memory per process, not per `run_bot` invocation, so all `/ws` pipelines share the same bridge (implicit rule now explicit, negative legacy: should be dependency-injected)
6. If `broadcast_text` is called with empty string, then the Text Bridge Avatar shall still send `{"type":"llm_text","text":""}` — frontend `handleLLMText` will create a talk stream with empty chunk (edge case now explicit; should be filtered)

### Requirement 3: Anam SDK Initialization and MediaStream Acquisition

**Objective:** As a browser, I want to initialize the Anam avatar and obtain the video/audio MediaStream, so that local rendering and Vonage publishing are possible

#### Acceptance Criteria
1. When `anamToken` is obtained, the Text Bridge Avatar shall create a client via `createClient(anamToken, {disableInputAudio:true})` (`static/script.js:67`) — `disableInputAudio:true` prevents Anam from capturing mic and echoing Vonage audio (implicit rule now explicit)
2. When the client is created, the Text Bridge Avatar shall register `AnamEvent.SESSION_READY` to log `Anam avatar ready` and `AnamEvent.CONNECTION_CLOSED` to log `Anam connection closed` (`static/script.js:71`)
3. When `await anamClient.stream()` succeeds, the Text Bridge Avatar shall store `streams[0]` as `anamStream` and render via `anamVideo.srcObject = anamStream; anamVideo.play()` (`static/script.js:80`) — `play()` may reject if autoplay blocked; rejection is caught at `static/script.js:87`
4. If `createClient` or `stream()` throws, then the Text Bridge Avatar shall log `Anam initialization error: {msg}` and continue to Vonage connection (degrade to audio-only) (`static/script.js:87`)
5. The Text Bridge Avatar shall always specify `disableInputAudio:true` to disable Anam microphone input and prevent duplicate input with Vonage audio — no flag shall allow it to be `false` in this demo

### Requirement 4: Text Streaming to Anam TTS

**Objective:** As a browser, I want to stream LLM text chunks to Anam TTS, so that streaming speech and lip-sync are achieved

#### Acceptance Criteria
1. When `wsAnam.onmessage` receives `{"type":"llm_text","text": "..."}` and `anamClient` exists, the Text Bridge Avatar shall create `currentTalkStream = anamClient.createTalkMessageStream()` if not yet created and execute `streamMessageChunk(text, false)` at `static/script.js:236` — `false` means not append-only but streamed chunk; multiple chunks reuse the same stream until `llm_end`
2. When `anamClient` does not exist, the Text Bridge Avatar shall fallback to `log('LLM: {text}')` (`static/script.js:231`)
3. When `{"type":"llm_end"}` is received, the Text Bridge Avatar shall call `endMessage()` if `currentTalkStream.isActive()` then reset `currentTalkStream = null` (`static/script.js:244`) — `isActive` guard prevents `endMessage` on already-closed stream
4. If `streamMessageChunk` or `endMessage` throws, then the Text Bridge Avatar shall log `Anam stream error: {msg}` without clearing `currentTalkStream` (retryable on next chunk) at `static/script.js:240`
5. When `handleInterrupt()` is called, the Text Bridge Avatar shall execute `currentTalkStream.endMessage()` then `anamClient.interruptPersona()` and set `currentTalkStream = null` (`static/script.js:256`) — note: `handleInterrupt` is currently defined but never invoked (dead code at `static/script.js:256`; gap flagged — should be wired to VAD interruption or removed)
6. If `anamStream` has empty `getVideoTracks`/`getAudioTracks`, then the Text Bridge Avatar shall skip avatar publish to Vonage and only log (edge case at `static/script.js:155`)

### Requirement 5: ws-anam Client Connection and Keepalive

**Objective:** As a browser, I want to monitor ws-anam connection state and detect disconnection, so that reconnect decisions and logging are appropriate

#### Acceptance Criteria
1. When ws-anam connection is needed in Step 5 of `connect()`, the Text Bridge Avatar shall create a WebSocket with `wsProto = (location.protocol==='https:' ? 'wss:' : 'ws:')` and `${wsProto}//${host}/ws-anam` (`static/script.js:181`)
2. When `wsAnam.onopen` fires, the Text Bridge Avatar shall log `Anam WS connected`
3. When `wsAnam.onclose` fires, the Text Bridge Avatar shall log `Anam WS disconnected`
4. When `wsAnam.onerror` fires, the Text Bridge Avatar shall log `Anam WS error: {type}`
5. While `wsAnam` is `OPEN`, the Text Bridge Avatar shall send `wsAnam.send('ping')` every 15 seconds (`static/script.js:210`) — note: `setInterval` at `static/script.js:210` is never cleared via `clearInterval` on `disconnect()` (bug/legacy flagged: leaks interval)
6. When `disconnect()` is called, the Text Bridge Avatar shall close `wsAnam` but shall also clear the ping interval (gap in current `static/script.js:277`; requirement now mandates `clearInterval`)

### Requirement 6: Non-Functional, Security, and Constraints

**Objective:** As a system, I want Text Bridge to degrade safely and remain observable, so that conversation continues even when cloud rendering fails

#### Acceptance Criteria
1. If the Anam API key is invalid and `POST /api/anam/session-token` returns 502, then the Text Bridge Avatar shall log `Anam token error` on the frontend and prepare to continue audio-only without blocking subsequent Vonage connection — current `static/script.js:42` returns early and blocks Vonage (gap flagged; should degrade)
2. The Text Bridge Avatar shall not persist `anamToken` in `localStorage` or URL; it shall keep it only in memory variable `let anamToken` at `static/script.js:35`
3. When some `ws` disconnect during `broadcast_text`, the Text Bridge Avatar shall continue delivery to remaining `ws` without aborting the whole broadcast — silent discard without logging is current behavior at `bot.py:73`; should log count (gap flagged)
4. The Text Bridge Avatar shall send the `text` field of `llm_text` as JSON without escaping, and prevent XSS by inserting `text` into `log` via `textContent` (`static/script.js:21` `d.textContent`) — `innerHTML` must never be used
5. The Text Bridge Avatar shall note that `LLMTextBridgeProcessor` at `bot.py:54` imports `WebSocket` from `fastapi` — coupling pipeline to FastAPI; should be abstracted to `typing.Protocol` with `send_json` (legacy flagged)
